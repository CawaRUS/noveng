# Документация команд NovEng v0.6.0

В этом файле перечислены все команды, доступные в движке **NovEng**. Команды пишутся в файлах сценария внутри фигурных скобок:

```
{команда:аргумент1|аргумент2|...}
```

Аргументы разделяются символом `|`. Пробелы вокруг аргументов обрезаются автоматически.

---

## 1. Сценарий: базовый синтаксис

Файлы сценария хранятся в `res/scenario/` и имеют расширение `.txt`. Движок распознаёт три типа строк:

1. **Имя персонажа:** `[Имя]` - задаёт текущего говорящего для последующих реплик.
2. **Текст:** обычная строка, выводится с эффектом печатной машинки.
3. **Команда:** `{команда:аргументы}` - выполняет игровое действие.

```
[Система]
Добро пожаловать в NovEng!
{set:score|0|int}
Система: Ваш счёт: $score$
```

---

## 2. Типы данных и переменные

NovEng поддерживает четыре типа переменных:

| Тип | Описание | Пример значения |
| :--- | :--- | :--- |
| `int` | Целое число | `42`, `-7` |
| `float` | Число с плавающей точкой | `3.14`, `-0.5` |
| `bool` | Логическое значение | `true`, `false` |
| `string` | Строка | `"hello"`, `NovEng` |

Имена переменных должны состоять из букв, цифр и символа подчёркивания, и не могут начинаться с цифры.

### Макросы `$var$`

Любая переменная может быть вставлена в текст реплики:

```
{set:hero|Алекс|string}
[Голос]
Рад тебя видеть, $hero$.
```

Макросы работают для всех типов: `int`, `float`, `bool`, `string`.

---

## 3. Скриптовые выражения

Многие команды принимают **выражения** вместо статических значений. Выражения поддерживают:

- Переменные: `$name$` или bare-идентификатор `name`
- Числа: `42`, `3.14`
- Строки: `"hello"`
- Булевы значения: `true`, `false`
- Арифметику: `+`, `-`, `*`, `/`, `%`, унарный `-`
- Сравнения: `==`, `!=`, `>`, `<`, `>=`, `<=`
- Логику: `&&`, `||`, `!`
- Скобки для группировки

```
{set:health|100|int}
{if:health > 50 && hasPotion == true|heal.txt|fight.txt}
{math:damage|$base$ * 1.5 + $crit$}
```

Если переменная не определена, она считается равной `0` / `false` / пустой строке в зависимости от контекста.

## 4. Команды визуальных эффектов и UI

| Команда | Аргументы | Описание |
| :--- | :--- | :--- |
| `clear` | - | Полная очистка экрана и истории диалогов. |
| `shake` | `frames\|intensity` | Тряска экрана. По умолчанию `15` кадров, сила `3`. |
| `color` | `Имя\|ANSI_Code` | Задаёт цвет имени персонажа. Коды `30-37` и `90-97`. |
| `banner` | `Текст` | Выводит текст в рамке из `=`, по центру. |
| `narrator` | `Текст` | Выводит текст от лица рассказчика (без имени). |
| `wait` | `ms` | Пауза в миллисекундах. |
| `type_speed` | `ms` | Устанавливает задержку между символами (`0-200` мс). |

```
{banner:Глава 1}
{narrator:Тихая ночь. Город спит.}
{wait:1000}
{color:Система|36}
```

## 5. Команды звука и музыки

| Команда | Аргументы | Описание |
| :--- | :--- | :--- |
| `play` | `file.mp3\|loop` | Запускает музыку из `res/music/`. Флаг `loop` зацикливает трек. |
| `stop_music` | - | Останавливает фоновую музыку. |
| `sfx` | `file.wav\|pitch` | Звуковой эффект из `res/sfx/`. `pitch` - высота звука. |
| `volume` | `0.0 - 1.0` | Общая громкость движка. |
| `type` | `Имя\|pitch` | Высота звука печати для конкретного персонажа. |

```
{play:ambient_base.mp3|loop}
{sfx:beep.wav|0.8}
{volume:0.5}
{type:Система|1.2}
```

## 6. Команды переменных и математики

| Команда | Аргументы | Описание |
| :--- | :--- | :--- |
| `set` | `key\|value\|type` | Создаёт или изменяет переменную. `type` опционален (`int`, `float`, `bool`, `string`). Без типа значение определяется автоматически. |
| `math` | `key\|expression` | Вычисляет выражение и сохраняет результат в переменную. |
| `inc` | `key\|delta` | Увеличивает переменную на `delta` (по умолчанию `1`). |
| `dec` | `key\|delta` | Уменьшает переменную на `delta` (по умолчанию `1`). |
| `clamp` | `key\|min\|max` | Ограничивает значение переменной диапазоном. |
| `random` | `min\|max\|var` | Записывает случайное целое `[min, max]` в переменную. |

```
{set:score|0|int}
{set:name|Игрок|string}
{inc:score|10}
{dec:lives|1}
{math:score|score * 2 + 5}
{clamp:health|0|100}
{random:1|100|luck}
```

## 7. Команды логики и навигации

| Команда | Аргументы | Описание |
| :--- | :--- | :--- |
| `if` | `expression\|true.txt\|false.txt` | Если выражение истинно, переходит к `true.txt`, иначе к `false.txt`. |
| `if` (legacy) | `key\|threshold\|true.txt\|false.txt` | Старый формат: `$key$ >= threshold`. |
| `choice` | `T1\|F1\|T2\|F2...` | Выводит список вариантов выбора. |
| `choice` (с условиями) | `T1\|F1\|C1\|T2\|F2\|C2...` | Варианты могут иметь условия; невидимые опции скрываются. |
| `chance` | `%\|win.txt\|lose.txt` | С вероятностью `%` переходит к `win.txt`. |
| `jump` | `file.txt` | Переход к другому файлу сценария. |
| `next_chapter` | `file.txt` | То же, что и `jump`. |
| `switch` | `expr\|case1\|file1\|case2\|file2...\|default.txt` | Сравнивает значение выражения с кейсами и переходит к подходящему файлу. Последний аргумент может быть файлом по умолчанию. |

```
{if:score >= 50|success.txt|fail.txt}
{choice:Рискнуть|jump_success.txt|Искать другой путь|search_path.txt}
{choice:Войти|enter.txt|hasKey == true|Уйти|leave.txt}
{chance:30|lucky.txt|unlucky.txt}
{jump:demo_bonus.txt}
{switch:$route$|good|demo_good.txt|bad|demo_bad.txt|demo_neutral.txt}
```

> **Примечание:** команды перехода (`if`, `choice`, `chance`, `jump`, `next_chapter`, `switch`) принимают только `.txt` файлы внутри `res/scenario/`. Попытка выйти за пределы директории блокируется.

## 8. Глобальные переменные (persistent)

Глобальные переменные сохраняются в `res/save/persistent.json` и переживают перезапуск игры и начало нового прохождения. Используются для флагов концовок, New Game+, достижений.

| Команда | Аргументы | Описание |
| :--- | :--- | :--- |
| `global_set` | `key\|value\|type` | Устанавливает глобальную переменную и сохраняет persistent-файл. |
| `global_math` | `key\|expression` | Вычисляет выражение и сохраняет результат как глобальную переменную. |
| `global_if` | `expression\|true.txt\|false.txt` | Проверяет выражение над глобальными переменными. |

```
{global_set:ending_good_seen|true|bool}
{global_set:ng_plus_count|0|int}
{global_math:ng_plus_count|ng_plus_count + 1}
{global_if:ending_good_seen == true|bonus_scene.txt|continue.txt}
```

Глобальные переменные автоматически загружаются при старте движка и доступны в обычных выражениях и макросах `$key$` (если нет локальной переменной с таким же именем).

---

## 9. Команды сохранений

| Команда | Аргументы | Описание |
| :--- | :--- | :--- |
| `autosave` | - | Принудительно создаёт автосохранение в слот ротации. |

Автосохранение также происходит автоматически каждые 5 диалогов и перед командой `{choice}`.

Ручные и автоматические сохранения управляются через меню паузы (`Esc` в игре) и главное меню.

## 10. Примеры сценариев

### Настройка атмосферы и персонажей

```
{color:Система|36}
{color:Голос|33}
{type:Система|1.2}
{type:Голос|0.7}
{play:ambient_base.mp3|loop}

[Система]
Инициализация протокола... $version$%
{sfx:beep.wav}
```

### Сюжетная развилка с переменными

```
{set:energy|10|int}
[Голос]
У нас хватит заряда для прыжка?

{choice:Рискнуть|jump_success.txt|Искать другой путь|search_path.txt}

// В другом файле:
{if:energy >= 50|super_jump.txt|fail_jump.txt}
```

### Экшен-сцена

```
[Голос]
Ложись!
{sfx:explosion.wav|0.5}
{shake:40|10}
{clear}
[Система]
Связь потеряна...
```

### Глобальные переменные для New Game+

```
{global_if:ng_plus_count > 0|new_game_plus.txt|normal_start.txt}
```

## 11. Технические детали

### Регистрация команд

Команды регистрируются автоматически через макрос `REGISTER_COMMAND` в `.cpp` файлах. Добавление новой команды не требует изменений в центральном коде движка.

### Безопасность

- Пути к сценариям проверяются: только `.txt` внутри `res/scenario/`, без `..`.
- ANSI-коды в `{color}` ограничены диапазоном `30-37` и `90-97`.
- Сохранения и `persistent.json` шифруются ChaCha20.
- Имена переменных и макросов валидируются на допустимые символы.

### Распространение

Исполняемый файл привязан к структуре ресурсов. Корневая директория активов (по умолчанию `res/`) должна поставляться вместе с приложением. Путь к ресурсам определяется макросом `DIR_RES` при сборке.
